# Celsius to Fahrenheit on Self-Managed Kubernetes (AWS EC2)

This repository deploys a small Flask application to a **self-managed Kubernetes cluster on AWS EC2**.

The purpose of the project is to demonstrate the complete deployment path:

```text
Source Code
    ↓
GitHub
    ↓
GitHub Actions
    ↓
Docker Hub
    ↓
Kubernetes
    ↓
ingress-nginx
    ↓
AWS Network Load Balancer
    ↓
Internet
```

> This cluster was built with `kubeadm`. It is not Amazon EKS.

---

## Architecture

```text
                         Internet
                            │
                            │ HTTP :80
                            ▼
                    AWS Network Load Balancer
                            │
                            │ TCP → NodePort
                 ┌──────────┴──────────┐
                 │                     │
              worker1               worker2
                 │                     │
                 └──── ingress-nginx ──┘
                            │
                         Ingress
                            │
                     ClusterIP Service
                            │
                       Flask Pods
```

Cluster layout:

```text
master
worker1
worker2
```

Reference environment:

| Component | Version / Configuration |
|---|---|
| OS | Ubuntu 26.04 LTS |
| Kubernetes | v1.37.1 |
| Runtime | containerd 2.2.2 |
| CNI | Calico v3.33 |
| Pod Network | 192.168.0.0/16 |
| Ingress | ingress-nginx |
| Load Balancer | AWS NLB |
| Container Registry | Docker Hub |

# Happy Path — Rebuild from Zero

## 1. Create the EC2 Nodes

Create three Ubuntu EC2 instances in the same VPC:

```text
master
worker1
worker2
```

Use a sufficiently large root disk. For this project, **20 GiB gp3 or larger** is recommended.

The nodes communicate using their private IP addresses.

Create separate Security Groups for:

```text
Master
Workers
NLB
```

The important network paths are:

```text
Kubernetes API       TCP 6443
Kubelet              TCP 10250
Calico VXLAN         UDP 4789
Ingress NodePort     NLB SG → Worker SG
```

Do not expose Kubernetes node ports or kubelet directly to the Internet.

---

## 2. Prepare Ubuntu on All Nodes

Run on:

```text
master
worker1
worker2
```

Disable swap:

```bash
sudo swapoff -a
```

Disable swap permanently in `/etc/fstab`.

Load the required kernel modules:

```bash
cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter
```

Configure kernel networking:

```bash
cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system
```

---

## 3. Install containerd

Run on all nodes:

```bash
sudo apt-get update
sudo apt-get install -y containerd

sudo mkdir -p /etc/containerd

containerd config default | sudo tee /etc/containerd/config.toml >/dev/null
```

Enable systemd cgroups:

```bash
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
```

Restart containerd:

```bash
sudo systemctl restart containerd
sudo systemctl enable containerd
```

Verify:

```bash
containerd --version
```

---

## 4. Install Kubernetes

Install compatible versions of:

```text
kubeadm
kubelet
kubectl
```

using the official Kubernetes package repository.

The reference cluster used:

```text
Kubernetes v1.37.1
```

After installation:

```bash
sudo apt-mark hold kubelet kubeadm kubectl
```

Verify:

```bash
kubeadm version
kubelet --version
kubectl version --client
```

---

## 5. Initialize the Control Plane

Run on `master`.

The cluster uses:

```text
Pod CIDR: 192.168.0.0/16
API Port: 6443
```

Initialize the cluster:

```bash
sudo kubeadm init   --control-plane-endpoint "<MASTER_ENDPOINT>:6443"   --pod-network-cidr=192.168.0.0/16
```

Configure kubectl:

```bash
mkdir -p $HOME/.kube

sudo cp /etc/kubernetes/admin.conf $HOME/.kube/config

sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

Check:

```bash
kubectl get nodes
```

Save the `kubeadm join` command securely.

Do not commit the join token or kubeconfig to Git.

---

## 6. Join the Workers

Run the join command generated by `kubeadm init` on both workers:

```bash
sudo kubeadm join <MASTER_ENDPOINT>:6443   --token <TOKEN>   --discovery-token-ca-cert-hash sha256:<HASH>
```

If the token expires, generate another one on the master:

```bash
sudo kubeadm token create --print-join-command
```

---

## 7. Install Calico

Install Calico using the official Tigera Operator manifests.

Reference version:

```text
Calico Open Source v3.33
```

Use:

```text
Pod CIDR:       192.168.0.0/16
Encapsulation:  VXLAN
```

If necessary, set the installation to VXLAN:

```bash
kubectl patch installation default --type='json'   -p='[{"op":"replace","path":"/spec/calicoNetwork/ipPools/0/encapsulation","value":"VXLAN"}]'
```

AWS Security Groups must allow Calico VXLAN between Kubernetes nodes:

```text
UDP 4789
```

Verify:

```bash
kubectl get nodes -o wide
```

Expected:

```text
master    Ready
worker1   Ready
worker2   Ready
```

Check Calico:

```bash
kubectl get pods -n calico-system -o wide
```

All required Calico pods should be Running.

---

## 8. Install ingress-nginx

Install the bare-metal ingress-nginx controller.

Reference version:

```text
ingress-nginx controller v1.13.3
```

```bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.13.3/deploy/static/provider/baremetal/deploy.yaml
```

Verify:

```bash
kubectl get pods -n ingress-nginx -o wide
```

Then find the generated NodePorts:

```bash
kubectl get svc -n ingress-nginx
```

The reference cluster used:

```text
HTTP  NodePort: 30142
HTTPS NodePort: 31723
```

These ports may be different after a fresh installation.

Use the values generated by the new cluster.

## 9. Application Kubernetes Configuration

The Kubernetes resources are already stored in the repository:

```text
k8s/
├── deployment.yml
├── service.yml
└── ingress.yml
```

Their responsibilities are:

```text
deployment.yml
    → application pods

service.yml
    → internal ClusterIP service

ingress.yml
    → routes ingress-nginx traffic to the application service
```

Do not manually duplicate these manifests during the rebuild.

They are deployed from the repository.

---

## 10. CI/CD Configuration

The GitHub Actions workflows are already stored under:

```text
.github/workflows/
```

The important workflows are:

```text
release.yml
    → test
    → build Docker image
    → push image to Docker Hub

prod-k8s-deployment.yml
    → connect to Kubernetes
    → apply Kubernetes resources
    → deploy the exact Docker image
    → wait for rollout
```

Required GitHub configuration includes the Docker Hub credentials and Kubernetes kubeconfig used by the workflow.

The deployment uses the Git commit SHA as the Docker image tag:

```text
brhmkskn/celsius-to-fahrenheit:<commit-sha>
```

This keeps the deployed Kubernetes version traceable to the exact source commit.

## 11. Deploy the Application

The normal deployment path is:

```text
local change
    ↓
git push
    ↓
GitHub Actions
    ↓
tests
    ↓
Docker image build
    ↓
Docker Hub
    ↓
Kubernetes deployment
```

Do not manually deploy the application from the master during the normal workflow.

After GitHub Actions completes:

```bash
kubectl get pods -o wide
```

Expected:

```text
2 application pods Running
```

Check the Kubernetes resources:

```bash
kubectl get deployment
kubectl get svc
kubectl get ingress
```

---

## 12. Test ingress-nginx on Both Workers

Before creating the AWS load balancer, verify that both workers can serve the ingress NodePort.

Using the actual HTTP NodePort:

```bash
curl http://<WORKER1_PRIVATE_IP>:<HTTP_NODEPORT>/
```

```bash
curl http://<WORKER2_PRIVATE_IP>:<HTTP_NODEPORT>/
```

Expected from both:

```text
HTTP 200
```

Do not continue to the NLB until both worker paths work.

---

## 13. Create the AWS Target Group

Create an AWS Target Group with:

```text
Target type: Instances
Protocol:    TCP
Port:        <ingress HTTP NodePort>
Health check: TCP
```

Reference configuration:

```text
Target Group: k8s-ingress-tcp
Port:         30142
```

Register:

```text
worker1
worker2
```

Wait until both become:

```text
Healthy
```

---

## 14. Create the Network Load Balancer

Create an Internet-facing AWS Network Load Balancer.

Reference:

```text
Name: k8s-ingress-nlb
```

Create the listener:

```text
TCP :80
    ↓
k8s-ingress-tcp
```

Use a dedicated Security Group for the NLB.

NLB inbound:

```text
TCP 80
Source: 0.0.0.0/0
```

Worker inbound:

```text
TCP <HTTP_NODEPORT>
Source: NLB Security Group
```

The worker NodePort should not be publicly exposed.

---

## 15. Test the Complete Path

Use the NLB DNS name:

```bash
curl -v http://<NLB-DNS-NAME>/
```

Expected:

```text
HTTP/1.1 200 OK
```

The complete request path is now:

```text
Internet
   ↓
AWS NLB
   ↓
Worker NodePort
   ↓
ingress-nginx
   ↓
Ingress
   ↓
ClusterIP Service
   ↓
Flask Pod :8080
```
